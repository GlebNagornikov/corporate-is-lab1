# План лабораторной №11 · «Книжная полка»

Этот план начинается с магазина после лабораторной №10. Он охватывает только оставшуюся работу.
[AGENTS.md](AGENTS.md) объясняет Codex, как устроен проект и какие решения использовать.
[Макет](docs/bookshop-design-concept.png) показывает главную на компьютере и карточку на телефоне.

В выданных файлах есть отсылка к таблицам лабораторной №0.3, но самих таблиц нет. Для работы
приняты **книжный магазин, модуль М1 «Отзывы и рейтинг» и лимит 5 экземпляров одного издания
на заказ**. Для М1 предлагается правило одного отзыва после доставки покупки. На КТ1 покажите
преподавателю эти решения и уточните официальный шифр. По вашему требованию в план входят
**все четыре модуля М1–М4** из части 3 и **все 14 расширений Р1–Р14** из части 4. М1 пока указан
как зачётный вариант. Если преподаватель назначит другой, отметьте его как зачётный в README.
Если появится текст №0.3, сверяйте правила по его пп. 11.2, 11.4 и 11.5 и при необходимости
уточните шаги. Здесь разобраны условия из выданной №11.

## Как пользоваться планом

1. Откройте рабочую папку в Codex. Отправляйте **один блок «Запрос для Codex» за раз**.
   В новом чате начинайте с того же блока и сообщайте номер последнего принятого шага.
2. Скопируйте команды из ответа Codex или попросите его выполнить их. Откройте указанный адрес
   и пройдите раздел «Как проверить». Попросите показать фактический результат команд, включая
   то, что потребовало вашей ручной проверки. После перемещения Django актуальные пути команд
   должны быть в AGENTS.md.
3. Если проверка не прошла, отправьте сообщение «Исправь шаг N. Я сделал …, ожидал …,
   увидел …». Дождитесь повторной проверки. Для изменений данных и проверки выпуска используйте
   отдельную тестовую базу или копию. Существующую базу перед переносом сохраните.
4. Попросите Codex показывать небольшие порции изменений и объяснять по одному месту в коде
   на шаг. Ведите обычную историю Git по контрольным точкам. Подготовьте минимум 25 осмысленных
   коммитов по реальным порциям работы, например перенос, форма, API, тест сценария, документация.
   До публикации проверьте ветку, которую будет открывать преподаватель. Приглашение отправьте
   сами. На КТ2 в README уже должен быть краткий список Р1–Р14.

Сроки от выдачи задания: КТ1 — неделя 1, КТ2 — неделя 3, КТ3 — неделя 5, КТ4 — начало
недели 6, защита — неделя 6. Конкретные даты объявляет преподаватель.

### Шаг 5. Довести покупку до правил книжного магазина

**Запрос для Codex**

> Сохрани отдельную проверку актуального остатка, блокировки, снимки цен, серверный расчёт,

> покупателя на чтение и действия только со своими заказами. Сохрани гостевую и серверную корзины
> и их объединение. Добавь недостающие API-тесты Б6, Б8, Б11 и тесты изменённого интерфейса.

**Как проверить**

- Выберите книгу с остатком не меньше 6. Для 5 экземпляров оформите заказ. Для 6 убедитесь,
  что UI объясняет лимит. Codex напрямую отправляет оформление с 6 экземплярами, в том числе
  разбитыми по вариантам. Ожидается 400 и сохранение корзины, остатка и числа заказов.
- С другой тестовой книгой положите 2 экземпляра, уменьшите остаток до 1 в тестовой базе,
  затем отправьте оформление. Код 400, поля React остаются на месте, лишнего списания нет.
  Повторите успешное оформление с подставной ценой и убедитесь, что в заказе серверная цена.
- Войдите в один аккаунт в двух независимых профилях и проверьте серверную корзину. Положите
  книгу в гостевую корзину и войдите, чтобы проверить объединение. Второй покупатель получает
  404 по ссылке на заказ и по API. Покупатель может отменить свой заказ только в допустимом состоянии.
