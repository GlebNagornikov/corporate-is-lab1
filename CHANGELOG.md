# Журнал изменений

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии —
[SemVer](https://semver.org/lang/ru/).

## [1.2.1] — 2026-11-07

### Исправлено

- В заказах менеджера основное действие показывается перед отменой независимо от порядка в API.

## [1.2.0] — 2026-11-07

### Добавлено

- Витрина на React и TypeScript: каталог с фильтрами в URL, карточка товара, вход и регистрация,
  корзина, оформление заказа, история заказов и раздел менеджера.
- API витрины: регистрация, `/api/auth/me/`, перенос гостевой корзины через `/api/cart/merge/`,
  допустимые переходы и возможность отмены заказа в полях `allowed_transitions` и `can_cancel`.
- Типизированный клиент витрины на основе схемы OpenAPI (`/api/schema/`, Swagger UI на `/api/docs/`).
- Сервис `frontend` для разработки и образ `shop-nginx` со сборкой React для HTTPS-стенда.
- Тесты фронтенда на Vitest, Testing Library и MSW, сквозные сценарии на Playwright.

### Изменено

- На HTTPS-стенде nginx обслуживает страницы витрины React. API, админка, `/healthz/` и платёжный
  webhook остаются в Django. Статика админки и изображения товаров раздаются из отдельных томов.
- HTML витрины перепроверяется при открытии, а файлы сборки с хешем кэшируются на год. Для SPA
  действует строгая CSP, страницы с формами и заказами загружаются по требованию.

### Исправлено

- При оформлении заказа через API отсутствие `delivery_method` возвращает `400` вместо `500`.
- В схеме API поля `parent` категории и `promo_code` заказа допускают `null`, а отзывы товара
  описаны как массив без пагинации.

## [1.1.2] — 2026-11-06

### Исправлено

- Кнопки избранного и сравнения видны в каталоге и на карточке товара. Добавление сохраняет текущую страницу и фильтры.
- У каждого варианта товара своя карточка с ценой и остатком. Корзина получает вариант открытой карточки.
- Основной адрес подставляется при оформлении заказа. Список сохранённых адресов открывается из редактируемого поля доставки.
- Отчёт по продажам доступен из списка заказов в панели менеджера. Статусы, способы доставки и заголовки переведены на русский в отчёте и в CSV.

## [1.1.1] — 2026-11-04

### Исправлено

- Демонстрационный сценарий использует отдельный CHECKPOINT10 и параметр --promo-code; существующий просроченный STUDENT10 не изменяется.

## [1.1.0] — 2026-11-04

### Добавлено

- Воспроизводимая подготовка buyer_demo/manager_demo и DEMO-товаров; README и полный сценарий HTTPS-проверки контрольной точки.

- №11: схема OpenAPI, Swagger для сотрудников в prod, описания/примеры API и лимиты 60/600/10 запросов в минуту.

- №12: JSON-логи Django/nginx, request-id в ответах и Celery, номер заказа отдельным полем.

- №10: Celery-worker и Redis-брокер в dev/prod, письма после commit, повторные попытки SMTP и сохраняемые задания.

- №9: Redis-кэш публичной карточки и меню, сброс после изменений, работа каталога при недоступном Redis.

- №6: отчёт продаж и CSV, агрегаты по периоду/статусу/доставке и топ-10 товаров с постоянным числом SQL-запросов.

- №8: учебный платёжный шлюз, HMAC-webhook и попытки оплаты; new → paid → confirmed, оплаченный заказ отменяет менеджер.

- №7: адресная книга с единственным основным адресом, выбор при оформлении и независимый снимок в заказе.

- №5: транзакционный CSV-импорт товаров/вариантов по артикулам, dry-run, отчёт ошибок строк и загрузка в admin.

- №4: уведомления о поступлении товара (любого варианта), отправка после commit без повторных подписок.

- №2: сравнение до четырёх товаров одной корневой категории, JSON-характеристики и подсветка различий.

- №1: избранное на сайте и в API, защита чужих списков и уникальность записей.

- №3: варианты товаров с собственными артикулами, ценами и остатками; выбор в корзине и снимок в заказе.

## [1.0.1] — 2026-11-04

### Исправлено

- Телефон в заказе приводится к формату +7XXXXXXXXXX; заказы с некорректным
  номером больше не принимаются ни через форму, ни через API.

## [1.0.0] — 2026-11-04

### Добавлено

- Каталог: дерево категорий, карточки товаров, скидки, фильтры, полнотекстовый поиск
  с русской морфологией и подсказками при опечатках.
- Отзывы с оценкой и модерацией, рейтинг товаров, галерея изображений.
- Корзина гостя и покупателя с объединением при входе.
- Оформление заказа: транзакционное списание остатков, промокоды, самовывоз,
  курьерская доставка и письма покупателю.
- Личный кабинет: история заказов и отмена нового заказа с возвратом остатков.
- Панель менеджера: допустимые переходы статусов, история изменений,
  группа «Менеджеры магазина» с ограниченными правами.
- Регистрация, собственная модель пользователя, учёт сотрудников и отделов.
- REST API каталога, корзины, заказов и сотрудников; аутентификация JWT и проверка прав.
- Docker: окружение разработки и отдельный прод-подобный стенд с многоэтапным
  образом, Gunicorn, nginx, HTTPS, раздачей static/media и отдельными миграциями.
- Проверка приложения и базы на `/healthz/` с номером версии, автоматические
  тесты и повторяемый сценарий проверки покупки по HTTPS.
