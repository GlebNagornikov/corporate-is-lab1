# Лабораторная №6 — часть 5

## Реализовано

- Панель заказов: статусы меняются только действиями через `change_status`; суммы, покупатель, промокод, позиции и история доступны только для чтения. Удаление заказов запрещено всем, включая суперпользователя.
- Дополнительная защита: создание заказа через admin тоже запрещено даже суперпользователю — иначе можно обойти транзакционный сервис оформления. Заказы создаются через магазин.
- Админка промокодов: поиск по коду, фильтр активности, счётчик использований в списке.
- Команда `setup_groups`: группа «Менеджеры магазина» получает ровно 12 прав из методички. Повторный запуск заменяет набор прав; миграции данных для группы не используются.
- 12 тестов из методички: 2 корзины, 7 сервисов заказов, 3 представлений.
- Ещё 6 тестов: идемпотентность и точный набор прав группы; видимые модели и запрет сотрудников/пользователей/корзин; readonly-поля и инлайны; запрет создания/удаления заказов даже суперпользователю; переходы через admin с письмами, журналом и возвратом остатка; права на промокоды.

## Локальный менеджер

Создана новая учебная учётная запись `manager`: `is_staff=True`, `is_superuser=False`, единственная группа «Менеджеры магазина», без личных дополнительных прав.
Поскольку в восстановленной базе не было сотрудников и отделов, создан учебный отдел «Продажи» и карточка «Учебный менеджер магазина»; учётная запись связана с этой карточкой. Это демонстрационные данные, не реальные кадровые сведения.

Случайный пароль записан вне репозитория: `../corporate_is-manager-access.txt`. Файл доступен только текущему пользователю Windows и SYSTEM. В Git и PR пароля нет.
Администратор по-прежнему использует отдельный пароль из `../corporate_is-local-access.txt`.

## Запуск

```powershell
docker compose up -d --build
docker compose exec web python manage.py migrate
docker compose exec web python manage.py setup_groups
docker compose exec web python manage.py test
```

Команду `setup_groups` выполняют после `migrate`, когда созданы Permission через `post_migrate`.
Новый клон не содержит локального менеджера и сотрудника: их нужно создать в admin и связать вручную.

- Магазин: http://localhost:8000/
- Панель: http://localhost:8000/admin/orders/order/
- Письма: http://localhost:8025/

## Границы работы

Части 6–7 не выполнялись: JWT, API корзины/заказов, `StrictDjangoModelPermissions`, быстрый тестовый хешер и coverage ещё не добавлены.
В частности, ограничение менеджера на сотрудников здесь относится к admin; API сотрудников остаётся открытым, как до части 6. Это учебный локальный стенд — не публикуйте его в интернет.
Исходная контрольная точка сохранена меткой `lab6-start-part5`; её описание — в `lab6-restoration.md`.

## Публикация

Ветка `feature/cart-orders`, PR предназначен только для `develop`, слияние — merge commit, без squash/rebase.
Так как опубликованный develop содержал только лабораторную №5, ветка включает также реконструированные части 2–4 с сохранённым описанием происхождения. Секреты, локальная БД, сотрудники и учётные записи не публикуются.
На этом ПК Git не имел авторизации для HTTPS push; публикация выполнена через подключённый GitHub-инструмент. Исходные локальные коммиты сохраняются в резервной ветке; рабочая ветка синхронизируется с опубликованной после проверки совпадения деревьев.
