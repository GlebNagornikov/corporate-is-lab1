# Лабораторная №10. Проверка самостоятельных заданий

## Состав сборки

В PowerShell выполните `$env:ANALYZE='1'; npm --prefix frontend run build`, затем откройте
`frontend/dist/stats.html`. Уберите переменную командой `Remove-Item Env:ANALYZE`.

В текущем основном файле крупнейшие модули по данным визуализатора: React DOM client
(529 536 байт), QueryObserver TanStack Query (13 069 байт) и scheduler React (9 044 байта).
Визуализатор показывает размеры модулей до итогового сжатия. Модули React DOM и scheduler
нужны при первом отображении. QueryObserver используется каталогом и навигацией. Для
дальнейшего уменьшения начальной загрузки можно исследовать загрузку страниц каталога и
деталей по требованию, измерив влияние дополнительных запросов на переходы.

## Предзагрузка

В DevTools откройте Network, выберите замедленную сеть и обновите каталог. Наведите курсор
на «Войти» и найдите запрос LoginPage. Добавьте товар в корзину, откройте её и наведите
курсор на «Оформить заказ». В списке запросов появится CheckoutPage до нажатия.

## nginx и настройки

Запустите стенд из этой ветки, задав отдельный APP_VERSION, и выполните
`docker compose -f docker-compose.prod.yml --env-file .env.prod ps`.
Сервис nginx должен получить состояние healthy. Проверка обращается к `/healthz/` через HTTPS.

Параметр `SUPPORT_PHONE` задаётся при запуске nginx. В подвале отображается его значение.
Проверьте `curl.exe -kI https://localhost/config.js`: ответ должен содержать `Cache-Control: no-store`.
Измените значение переменной и пересоздайте контейнер nginx с тем же образом, чтобы проверить
новый телефон без пересборки. Допускаются цифры, пробел, плюс, скобки и дефис.
