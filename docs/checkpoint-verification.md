## Проверка доработок

Таблица всех ручных сценариев и тестовых модулей находится в README.
Дополнительно добавлен `scripts/check_checkpoint.py`: проходит через настоящий HTTPS
и формы входа/JWT, проверяет избранное, сравнение, адрес, варианты, заказ с промокодом,
HMAC-платёж с отказом/успехом/повтором/неверной подписью, ограничения отмены,
обработку менеджером, отчёт/CSV, Swagger и admin.

```powershell
python scripts/check_checkpoint.py --expected-version 1.1.0
```

Скрипт использует публичные локальные demo-аккаунты из README. Он создаёт тестовые
адреса, заказы и попытки оплаты в демонстрационной базе. Проверка SMTP/Redis и тесты
не требуют передачи каких-либо настоящих платёжных данных.

## Найденные и устранённые пересечения

- Варианты имеют свои строки корзины; чужие/неактивные варианты и обход через скрытый
  стандартный вариант отклоняются. Для основного варианта введён уникальный индекс.
- Покупка блокирует корзину от повторного оформления и блокирует товар перед вариантом.
- Остатки вариантов пересчитывают публичный остаток; поступление отслеживается по товару.
- Кэш не содержит персональных данных. Массовая модерация, checkout и отмена его сбрасывают.
- Кэш, очередь и throttling разделены на DB1/DB0/DB2 Redis. Короткий circuit breaker
  предотвращает повторные зависающие подключения, DNS-таймаут ограничен в web.
- nginx повторно разрешает адрес web через Docker DNS при пересоздании контейнера.
- Письма сохраняются как задания, выполняются после commit, повторяются при SMTP-ошибках;
  повторная обработка отправленного задания не отправляет письмо ещё раз.
- Отчёт явно определяет выручку и не размножает суммы заказов через JOIN позиций.

Релиз 1.1.0 выпускается через release/1.1.0 → main merge-коммитом,
аннотированный тег v1.1.0 и обратное слияние в develop. Финальный образ собирается
из чистого тега. Результат его развёртывания и состояние Git сообщаются в итоговом ответе.
