# Лабораторная №5: дополнительные задания

## Что изменилось

- `Product.clean()` возвращает ошибку поля `old_price`, если старая цена меньше или равна текущей. Ограничение PostgreSQL сохранено: `save()` в обход валидации по-прежнему защищён базой. В списке admin теперь можно менять и старую цену, чтобы проверка работала также при массовой правке цен.
- `ProductQuerySet.search()` использует `SearchHeadline` с русским словарём для названия и фрагмента описания. Шаблонный фильтр экранирует HTML и разрешает только теги `<mark>` без атрибутов. Подсветка появляется на витрине при поиске; формат API не изменён.
- Общий `ProductFilter.rating_min` фильтрует средний рейтинг опубликованных отзывов, включая границу. Поддерживаются дробные значения от 0 до 5. Товары без опубликованных отзывов не проходят заданный порог, даже 0. Пустой параметр отключает фильтр. API возвращает 400 на нечисловое значение или выход за диапазон; витрина показывает ошибку возле поля.
- `ProductImage` хранит дополнительные фото, описание и порядок. `TabularInline` позволяет добавлять и удалять их в admin. Фото выводятся на странице товара по порядку, затем по id. Основное поле `Product.image` и существующие фото не меняются. В API галерея не добавлялась. Связь подгружается через `prefetch_related`.
- Миграция: `catalog/0003_productimage.py`. Загруженные изображения остаются в `media/`, не в Git. Удаление записи фото не удаляет физический файл из хранилища автоматически.

## Запуск и автоматические проверки

Команды выполняются из корня проекта при зап��щенном Docker Desktop:

```sh
docker compose up -d
docker compose exec web python manage.py migrate
docker compose exec web python manage.py check
docker compose exec web python manage.py makemigrations --check --dry-run
docker compose exec web python manage.py test catalog
docker compose exec web python -m ruff check .
docker compose exec web python -m ruff format --check .
```

Новые зависимости не добавлялись, пересборка образа не нужна. Не выполняйте `docker compose down -v`: команда удаляет данные базы.

## Ручная проверка

### 1. Проверка старой цены

1. Открыть http://localhost:8000/admin/catalog/product/ и выбрать товар.
2. Установить цену 1000, старую цену 900. Сохранить.
3. Форма остаётся открытой, возле старой цены появляется «Старая цена должна быть больше текущей.», ошибки сервера нет.
4. Проверить старую цену 1000 — та же ошибка. Значение 1200 или пустое поле сохраняется.
5. Повторить неправильное сочетание цен через редактирование в списке товаров admin.

### 2. Подсветка поиска

1. Открыть http://localhost:8000/?q=ноутбуки (если демокаталог уже заполнен).
2. В результатах «Ноутбук» выделен цветом, несмотря на другую форму слова в запросе. Совпадения в фрагменте описания тоже выделены.
3. Открыть http://localhost:8000/ без запроса — подсветки и поисковых фрагментов нет.
4. Поиск с опечаткой `наушнеки` по-прежнему показывает подсказки.

### 3. Минимальный рейтинг

1. Через admin создать опубликованные отзывы: для товара A оценки 5 и 3 от разных покупателей (среднее 4); для B — 3; C оставить без отзывов.
2. Открыть http://localhost:8000/?rating_min=4 и http://localhost:8000/api/catalog/products/?rating_min=4 — A проходит, B и C не проходят.
3. Добавить A скрытый отзыв с оценкой 1: результат не меняется. Опубликовать его: среднее становится 3, A пропадает из выборки.
4. Проверить `rating_min=4.5`, совместную ��ильтрацию с ценой/категорией, очистку поля и сохранение параметра при пагинации.
5. API с `rating_min=abc` или `rating_min=6` должен вернуть 400 с ошибкой поля.

### 4. Несколько фото

1. Открыть товар в admin. Внизу находится таблица «Фото товара».
2. Добавить два PNG/JPEG, заполнить описания и порядок (например, 2 и 1), сохранить.
3. Открыть страницу этого товара на витрине: основное фото сохранено, дополнительные показаны в заданном порядке. Нажатие открывает оригинал.
4. Изменить порядок, затем удалить одно фото через флажок удаления inline — витрина отражает изменения.
5. Проверить товар без основного фото, но с дополнительными: галерея также отображается.

Автотесты покрывают модельную и admin-валидацию (включая list_editable), морфологию и XSS-экранирование подсветки, фильтры витрины/API, скрытые отзывы, дробные и неверные пороги, загрузку фото через inline, порядок, каскадное удаление записей и отсутствие N+1. Исходный тест на 4 SQL-запроса каталога сохранён.
